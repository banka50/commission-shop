# Комиссионный магазин

Веб-приложение для автоматизации работы комиссионного магазина. Построено на Flask + SQLAlchemy.

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd src
python app.py
```

Приложение запустится на `http://127.0.0.1:5000`.

Настройка БД — в `src/config.toml` или `src/.env`. По умолчанию используется PostgreSQL.

### Конфигурация

Настройки задаются тремя способами (приоритет от высшего к низшему):

1. **Переменные окружения** — заданные в терминале или системе
2. **`src/.env`** — файл с переменными окружения
3. **`src/config.toml`** — файл конфигурации

Ключевые переменные:

| Переменная | Описание | По умолчанию |
|---|---|---|
| `DB_ENGINE` | СУБД: `postgresql`, `sqlite`, `mysql` | `postgresql` |
| `POSTGRES_HOST` | Хост PostgreSQL | `127.0.0.1` |
| `POSTGRES_PORT` | Порт PostgreSQL | `5432` |
| `POSTGRES_DB` | Имя базы данных | `db` |
| `POSTGRES_USER` | Пользователь PostgreSQL | `postgres` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL | `root` |
| `SQLITE_PATH` | Путь к файлу SQLite | `commission_shop.db` |
| `SECRET_KEY` | Секретный ключ Flask | `supersecretkey` |

Для быстрого старта без сервера БД — используйте SQLite:
```bash
# src/.env
DB_ENGINE=sqlite
```

## Workflow

### 1. Регистрация комитента

Прежде чем принять товар, нужно зарегистрировать комитента — человека, который сдаёт вещи на реализацию.

**Комитенты → Добавить комитента** — заполнить ФИО, контакты, паспортные данные, ИНН.

---

### 2. Приёмка товара

Когда комитент приносит вещи:

1. **Акты приёма → Добавить акт приёма** — указать номер акта, дату, комитента.
2. Открыть созданный акт → нажать **«Добавить товар»** — ввести наименование, описание, цену, даты.
3. Повторить для каждого принесённого товара.

Все товары акта видны прямо на его странице.

---

### 3. Оформление продажи

Когда товар продан:

1. Открыть нужный товар (**Товары** → выбрать или со страницы акта приёма).
2. Нажать **«Оформить продажу»** — форма откроется с уже выбранным товаром.
3. Заполнить дату, цену продажи, комиссию и статус (*Оплачено / Ожидает / Возврат*).

Если клиент вернул товар — поменяй статус продажи на **Возврат**, затем оформи новую продажу тем же способом. Вся история продаж по каждому товару хранится и видна на его странице.

---

### 4. Отчёты по продажам

Для формирования периодической отчётности:

**Отчёты по продажам → Добавить отчёт** — выбрать тип (*Ежедневный / Еженедельный / Ежемесячный / Квартальный / Годовой*), указать дату и описание.

---

## Структура данных

```
Consignor (комитент)
    └── ConsignorReport (акт приёма)
            └── Product (товар)
                    ←── Sale (продажа, может быть несколько)

SalesReport (отчёт по продажам) — самостоятельный документ
```

### Consignor — комитент
| Поле | Тип | Описание |
|---|---|---|
| last_name, first_name, middle_name | varchar | ФИО |
| email | varchar | Уникальный email |
| phone_number | varchar | Уникальный номер телефона |
| passport_data | varchar | Паспортные данные (уникальные) |
| inn | varchar(12) | ИНН (уникальный) |

### ConsignorReport — акт приёма товара
| Поле | Тип | Описание |
|---|---|---|
| number | varchar | Уникальный номер акта |
| date | date | Дата приёма |
| description | varchar | Описание |
| consignor_id | FK | Комитент, сдавший товар |

### Product — товар
| Поле | Тип | Описание |
|---|---|---|
| product_name | varchar | Наименование |
| description | varchar | Описание (необязательно) |
| delivery_date | date | Дата приёма на реализацию |
| expiry_date | date | Срок реализации |
| price | numeric(10,2) | Цена |
| consignor_report_id | FK | Акт приёма, по которому поступил товар |

### Sale — продажа
| Поле | Тип | Описание |
|---|---|---|
| product_id | FK | Товар, который был продан |
| sale_date | date | Дата продажи |
| sale_price | numeric(10,2) | Цена продажи |
| commission | numeric(10,2) | Комиссия магазина |
| status | enum | `Оплачено` / `Ожидает` / `Возврат` |

### SalesReport — отчёт по продажам
| Поле | Тип | Описание |
|---|---|---|
| number | varchar | Уникальный номер отчёта |
| date | date | Дата отчёта |
| report_type | enum | `Ежедневный` / `Еженедельный` / `Ежемесячный` / `Квартальный` / `Годовой` |
| description | varchar | Описание (необязательно) |
